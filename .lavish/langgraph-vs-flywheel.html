LangGraph vs flywheel x toron x beads

What LangGraph actually guarantees, where we already beat it, the one real gap, and what to borrow.

Bead bd-ysct · pin brash-otter · 2026-09-26 · read from official docs + repo source, not run

The decision

Do we adopt LangGraph, borrow from it, or leave it alone?

Borrow four ideas. Reject the engine. One borrow is urgent and unblocks bead bd-6si7. Adopting LangGraph would add a second orchestration authority to the stack whose P1 bead is removing the first one — and would trade away four things we are strictly better at.

Tick Law reducer — ours durable exec via Resonate — ours signed remote approval — ours fail-closed effect journal — ours run-state checkpoint — MISSING time travel / fork — MISSING presence, FCFS, fences — N/A to LangGraph

Where LangGraph even applies

LangGraph assumes one process owns the graph. Roughly 40% of our stack is distributed-consensus work it cannot touch at all.

Read this before the tables. The middle band is the only band where LangGraph teaches us something we do not have. It is also the band that maps directly onto bd-6si7 (ADR-0016), which is already the P1 bead. The bottom band is why this is a borrow, not a migration.

The one real gap

We say "checkpoint". We do not mean what LangGraph means.

LangGraph checkpoint

A replayable snapshot of graph state at a superstep boundary, keyed (thread_id, checkpoint_id). The substrate for replay, fork, and partial-superstep recovery.

It answers: "what was the state of run X after step 3?"

Our checkpoint

src/state.rs:1556 — a swarm roster snapshot. No graph state, no step, no replay.

struct Checkpoint {
  ts, project, message,
  workspace_id: Option<String>,
  agents: Vec<CheckpointAgent>,  // name, kind, status, pane_id
  git_head: Option<String>,
}

It answers: "who was in the swarm and what pane?" Nothing about run state.

This is a vocabulary trap. Anyone arriving from LangGraph will read flywheel checkpoint as replayable state and be wrong. Our own reducer state is recovered by projection seeding — seed_swarm_resume reads persisted counters and reseeds the model. That is not replay, and it is not a state log.

Why the borrow is cheap for us

Our Tick Law already did the hard part. A pure reducer makes a state snapshot a value, not a reconstruction.

The asymmetry that matters. LangGraph pushes at-most-once onto the node author and says so in a Warning. We enforce it in the host, per effect, and EffectJournalMode::Enforced refuses an effectful leaf that has no journal. That is strictly better and must not regress.

Guarantee by guarantee

Each LangGraph guarantee against what we actually have. Aligned so the difference does not need hunting.

Per-key reducers, one writer partial They have ReduceOp as a 5-value enum reachable only through one reduce action. We do not have reducers as a property of each state field. Authority is spread over WorkspaceModel, DoorbellModel, LoopModel, doorbell-rt::Brain, ActiveLoop, JSONL, and SQLite. Promote ReduceOp to a per-field property and make the reducer the only mutation path. Design move, not a dependency. This is ADR-0016's mechanism.
Pregel supersteps yes Same shape, different name. tick(model, msg) -> (model, cmds) at workspace.rs:1561 and durable.rs:568. 22 Msg variants, no I/O in the tick. Nothing. Already Elm-strict and already law-documented.
Checkpoint per superstep no No state log anywhere. Our Checkpoint is a roster snapshot. Recovery is projection seeding, not replay. B2. Write (seq, model, next_msg) after each tick. Pure reducer makes it a value.
Pending writes better Theirs is per-node, and recovering a partial superstep is a feature they had to add. Ours is per effect with derive_effect_key, and a missing journal refuses the effect. Nothing. Reuse the existing rows as the pending-write source.
interrupt / resume better Theirs is an in-process value you pass back. Ours: request_approval → Resonate promise → kind-46011 → operator signs → parked fn unblocks. Survives a process crash, and works from another machine. Nothing. ParkKind, PendingRegistry, validate_resolution already cover it.
Time travel / fork no Zero hits for time_travel, fork, rewind, get_state_history in any .rs in either repo. Debugging a failed run is log archaeology. B3, and it depends on B2. Highest user-visible payoff.
Durability modes better Theirs: exit / async / sync — a pure performance ladder. Ours: Recording / Enforced — a correctness switch, because Enforced fails closed. B4. Name the third point explicitly so the choice is visible. Do not adopt a performance-only ladder.
Per-node retry / timeout yes Ours is richer on the failure side: ActionStage (normalize/input/execute/output/effect/park), ProviderErrorClass, EvidenceRef, FailureKind. Theirs is richer on the clock: idle-vs-run timeout with heartbeat refresh. B6. Read NodeTimeoutError before redesigning breaker.rs. Do not import it to get it.
Idempotency = author's job better They warn in three places that you must make side effects idempotent. We enforce it in the host and journal before the provider runs. Nothing. Strict regression if adopted.
Compile-time validation better Their compile() checks for orphaned nodes. We have 1378 lines of workflow lint, 1143 of playbook lint, and a closed 6-value Phase vocabulary that rejects unknown variants at parse time. Nothing. A deliberate safety choice made at real cost.
Honest missing status better Theirs has get_state_history but no rule that a status-less row is a hole. Ours: history_row_status reads unknown, never a default done, and annotation rows declare themselves. Nothing. Preserve under any redesign.
Studio / visual graph no No live graph view. artifacts stitch renders evidence and herdr panes are the live UI, but there is no "show me this run's graph and where it is". Separate question from LangGraph. herdr already wins for a real terminal.

Note the pattern. Of twelve guarantees, we match four, beat five, partially have one, and genuinely lack three. LangGraph is not ahead of this stack — it is adjacent to it, and ahead in exactly the places our own ADR-0016 already identified.

What we would give up by adopting

The cost side, made as visible as the benefit.

Lost outright
  • Fail-closed journaling. Enforced mode has no LangGraph equivalent. Their model is "author writes idempotent code".
  • Signed remote approval. A Nostr-signed kind-46011 from another machine vs an in-process value.
  • Closed vocabularies + lint gates. Their compile() checks orphaned nodes; we reject unknown phase variants at parse.
  • Honest run ledger. The unknown-not-done rule has no counterpart.
  • Nostr-native identity. One pin, one npub, across every surface.
New problems created
  • A second graph engine beside toron-workflow + Resonate, in a stack whose P1 bead is authority de-duplication.
  • Python in a Rust stack, or a JS sidecar with its own deploy and failure modes.
  • LangChain coupling for the parts that matter: callbacks, store, tracing.
  • A second checkpoint store to reconcile against effect_journal.
  • A second UI on top of herdr, for a workload where a real terminal is the right surface.

The borrow list

Ranked. Cost is stated, not implied.

B1 · urgent

Per-state-key reducers

The single highest-leverage idea in the comparison, and it is a design move rather than a dependency.

Do: every state key names its merge function; exactly one writer per key.
Cost: touches every reducer — the bd-6si7 work already scoped.
Risk: reducers that accumulate hide bugs. Needs a deliberate override, the way LangGraph's Overwrite does.

B2 · urgent

State log + pending writes

The capability gap. Cheap for us specifically because tick is already pure.

Do: write (seq, model, next_msg) per tick; reuse effect rows as pending writes.
Cost: one new store, one conformance suite, a retention story (checkpoints grow unbounded — LangGraph hit this too).
Risk: our honest-unknown case: an effect left InFlight on crash must not read as success.

B3 · high value

Time travel as a verb

The change an operator would actually notice.

Do: flywheel workflow replay <run_id> --from <seq> and --fork.
Cost: small once B2 lands.
Risk: forking a run that dispatched real external effects. Fork must be dry-by-default.

B4 · cheap

Durability-mode vocabulary

Ours is the better model with an unnamed third point.

Do: name the third mode explicitly (Deferred?) so the choice is visible rather than implied.
Cost: naming plus a lint rule.
Risk: adopting their performance-only ladder and losing the fail-closed point.

B5 · cheap

Checkpointer conformance suite

Directly targets our transition-table drift risk (durable.rs:299).

Do: require any journal or state-log backend to pass a contract suite before it counts as a backend.
Cost: one test crate.
Risk: low. This is the cheapest drift preventer on the list.

B6 · read, do not import

NodeTimeoutError

Their idle-vs-run timeout with heartbeat refresh beats our breaker on expressiveness.

Do: read it before redesigning breaker.rs.
Cost: zero.
Risk: importing the Python runtime to get the feature.

Also worth mirroring, not on the numbered list: their error_handler(state, error) -> Command Saga-compensation pattern. Our compose grammar has retry(n): but no first-class compensating action. That is a real small gap, and it is cheap.

Assumptions that would change this

State these plainly, because if any is wrong the recommendation moves.

LangGraph was read, not run. Judged from official docs and the repo README. No benchmark, no side-by-side execution. Any claim about relative performance is absent here on purpose.
Version-sensitive. Timeouts, per-node error handlers, set_node_defaults, and DeltaChannel all require langgraph>=1.2. DeltaChannel is beta.
The deepest mismatch is single-process ownership. If our hardest problems are distributed consensus, then a graph library is the wrong category of tool, and the bottom band above is larger than I have drawn it.
Our gap findings are absence-of-evidence plus ADR-0016's own statement. Grep found nothing; that is not proof. Confirm against the bd-6si7 plan before B1 and B2 are sized.
Resonate stays. If durable execution moves off Resonate, the whole comparison shifts, because LangGraph's L6 is the one thing we currently get from a dependency rather than from ourselves.
