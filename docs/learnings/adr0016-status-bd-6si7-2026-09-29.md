# ADR-0016: what is proven, what is not, and the argument against closing (bd-6si7)

## What the epic's verify actually says

`mbx +nightly-aarch64-apple-darwin test` is green at 2092 bin tests and
`bash scripts/verify-clippy.sh` exits 0. That is the bead's verify string,
and it passes.

The problem: that verify would also have passed before this session's work,
and it would keep passing if half the architecture were deleted, because a
green suite is a statement about the code as written, never about the
guarantees as INTENDED. A guarantee with no tripwire is a comment, and a
comment is exactly what a refactor deletes without noticing.

## The counter-argument, stated as if I were reviewing my own close

**Claim under review:** ADR-0016 is fully implemented.

**Against it.** Eight numbered decisions and nine invariants are not
binary. The repo's own audit note (AGENTS.md, 2026-09-22) called this
verdict *conditional* and named two gaps. "Implemented" therefore cannot be
established by a passing test command; it can only be established by a
named enforcement point per invariant. Until those enforcement points
exist and are themselves tested, the honest verdict is "the architecture
is present and the suite is green", which is weaker than "implemented".

**What changed the verdict.** Two things, both measured rather than assumed.

1. Both audit gaps were real gaps, and one was still open.
   - Jev self-resolving `RuntimeAuthority`: CLOSED already. Every
     `RuntimeAuthority::for_test` call site is inside a test module; the
     14 production `resolve()` sites are host edges (main, doorbell_host,
     the Resonate registration block), which is precisely where the effect
     law allows the world to run.
   - Durable leaves sampling the clock: WAS STILL OPEN, at
     `durable::fresh_loop_id`, which built a durable promise id from
     `SystemTime::now()`. That is the worst possible place for an ambient
     read: the id IS the replay identity, so the same inputs produced a
     different id on every replay. Fixed in `405285b` by injecting the
     stamp from the host edge.

2. A guarantee with no tripwire is a comment, so the tripwires themselves
   now have a gate (`src/adr0016_invariants.rs`, 7 tests). It asserts that
   all nine invariants still have a named enforcement point. Renaming one
   reducer determinism test turns it red; that is the proof it is not
   theatre.

## The law that made the second gap findable

Not "any direct clock read is a violation". That rule is wrong and would
have produced a worse codebase. The law is narrower:

- A LEAF that must be replayed and substitutable receives time as an
  argument. `fresh_loop_id` violated it.
- A POLICY layer may bind a clock. `run_leaf_cmd_bounded` samples
  `Instant::now()` to enforce a deadline, and that is the timeout policy
  itself (effect law 10: every wait is bounded). Rewriting it to take an
  injected clock would make the bound untestable in the only place that
  matters.
- An INTERPRETER runs the world. daemon ticks, doorbell_host, herdr_shim,
  pane, run_log and write_liveness all sample time, and every one of them
  is on the host side of the fold.

So the audit gap was one real violation, not twenty-nine. Counting
occurrences instead of classifying them would have produced a large,
wrong, and unmaintainable diff.

## The honest residual

`docs/decisions/0016-...md` section 8 (module boundaries) and section 6
(doorbell runtime as interpreter) are architectural statements that no
test can fully adjudicate. The invariant gate names the enforcement points
that exist; it does not invent ones that do not. If someone later claims
section 6 is done, the proof must be a named interpreter, not a green
build.
